# Бухгалтерская модель

Книги ведутся в базовой валюте компании, документы — в своих валютах. Все суммы —
целые минимальные единицы; курсы — точные дроби из десятичных строк.

## План счетов

| Счёт | Название | Где в чистых книгах |
|---|---|---|
| 1010 | Bank | поступления, возвраты, расходы |
| 1200 | Accounts receivable | счета, погашения, кредит-ноты, сторно |
| 2150 | Unapplied receipts | двухшаговая разноска, неопознанные поступления |
| 2200 | Customer advances | авансы, переплаты, возвраты (только базовая валюта) |
| 4000 | Revenue | выставление счетов |
| 4100 | Sales returns | кредит-ноты |
| 6100 | Bank charges | комиссия банка |
| 6200–6900 | Operating expenses | прочие расходы (шум) |
| 7100 | Realized FX gain/loss | курсовая разница при погашении |

## Конвертация

`conv(x, r) = sign(x) · round_policy(|x| · r · 10^(e_base − e_doc))`

- Курс — сколько единиц базовой валюты за 1 единицу валюты документа.
- Дата курса — **местная дата события компании** (по `policy.period.timezone`),
  правило `policy.fx.rate_date`: `same_day_or_previous` или
  `previous_day_or_earlier`, назад не больше `max_lookback_days` (5) дней.
  На выходные курса нет — берётся предыдущий рабочий день.
- Округление `policy.rounding.mode`: `half_even` или `half_up` (ничья — от нуля).

## Правила проводок

| Событие | Проводка |
|---|---|
| Счёт T | Дт 1200 A / Кт 4000 A, A = conv(T) по дате счёта |
| Кредит-нота (полное аннулирование) | Дт 4100 / Кт 1200 на остаток A счёта |
| Сторно и перепроведение | ошибочная Дт 1200 / Кт 4000, зеркальное сторно Дт 4000 / Кт 1200, верная — все в одном периоде |
| Поступление, прямое | Дт 1010 (conv(P) − conv(fee)), Дт 6100 conv(fee) / Кт 1200 погашения, Кт 2200 conv(переплаты), ± одна строка 7100 |
| Поступление, двухшаговое | 1) Дт 1010, Дт 6100 / Кт 2150 conv(P); 2) через 0–3 дня Дт 2150 / Кт 1200 погашения ± 7100 |
| Неопознанное поступление | Дт 1010 / Кт 2150, может остаться до конца выгрузки (`invoice_refs = null`) |
| Аванс | Дт 1010 / Кт 2200 (только базовая валюта) |
| Возврат | Дт 2200 / Кт 1010, отрицательная сумма платежа |
| Прочие расходы | Дт 62xx / Кт 1010, ссылки null |

`amount_minor` платежа — брутто (сколько отправил клиент), `fee_minor` — комиссия,
удержанная банком.

## Погашение по историческому курсу

- Погашение части `a` счёта T = round(a · A / T), где A — проведённая сумма счёта.
- **Закрывающее** погашение — событие, после которого применённая сумма достигает
  T (события упорядочены по времени события: платёж, кредит-нота). Оно берёт точный
  остаток A − Σ прежних погашений.
- Строка 7100 — одна на проводку, гасящую 1200; нулевую не создаём.
- Если счёт проведён дважды (ошибка), погашение считается от A **одной** проводки.

## Инварианты чистых книг

| № | Инвариант |
|---|---|
| I1 | Σ дебет = Σ кредит |
| I2 | каждая проводка (строки одного момента) сбалансирована; у разных проводок разные моменты |
| I3 | нетто выставления и сторно по счёту: Дт 1200 = conv(T) по дате счёта |
| I4 | по каждому поступлению: Дт 1010 + Дт 6100 = conv(amount) |
| I5 | разница при погашении — ровно одна строка 7100 или ноль |
| I6 | остаток 1200 по счёту ≥ 0; у оплаченного или аннулированного = 0 |
| I8 | 2150 по каждому платежу с распределением обнуляется до конца выгрузки |
| I9 | проводка в том же периоде, что и событие (кроме переклассификаций) |
| I10 | ID глобально уникальны, все не-null ссылки существуют |
| I12 | ни одной метки ближе 60 с к границам периода |
| I13 | total = Σ amount; amount = quantity × unit_price |
| I14 | в строке ровно одна сторона > 0; валюта = базовая; счёт из плана |
| I15 | каждый документ окна проведён внутри окна |
| I16 | (дата, пара) в fx уникальна; курс > 0 |
| I17 | валюта платежа = валюта счетов в ссылках; Σ распределений ≤ открытой сумме |
| I18 | остаток 2200 по клиенту не уходит в минус во времени |

Генератор проверяет их перед внесением ошибок (`books.check_invariants`),
независимый проверяльщик — по файлам `private/clean/` (отчёт A).

## Упрощения

- Нет переоценки открытой валютной дебиторки на конец периода (IAS 21.23) —
  поэтому погашение идёт по историческому курсу.
- Выручка признаётся по дате счёта (`revenue_basis = invoice_date`), а не по IFRS 15.
- Один мультивалютный банковский счёт; нет НДС и резервов.
- Кредит-ноты — только полное аннулирование.

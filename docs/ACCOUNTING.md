# Бухгалтерская модель

Книги ведутся в базовой валюте компании, документы — в своих валютах. Все суммы —
целые минимальные единицы; курсы — точные дроби из десятичных строк.

## План счетов

| Счёт | Название | Где в чистых книгах |
|---|---|---|
| 1010 | Bank | поступления, возвраты покупателям, прочие операции |
| 1200 | Accounts receivable | счета, списание задолженности при оплате, кредит-ноты, сторно |
| 2150 | Unapplied receipts | нераспределённые (неразнесённые) поступления: разноска в два этапа, невыясненные поступления, неразнесённая часть платежа |
| 2200 | Customer advances | авансы полученные, переплаты, возвраты переплат (только базовая валюта) |
| 4000 | Revenue | выставление счетов |
| 4100 | Sales credits (credit notes) | корректировки выручки: кредит-ноты на полную сумму |
| 6100 | Bank charges | комиссия банка |
| 6200–6900 | Operating expenses | прочие операции (фон) |
| 7100 | Realized FX gain/loss | реализованная курсовая разница; кредит — доход, дебет — расход |

Начальных остатков нет: все счета, которые гасятся в выгрузке, выставлены внутри
неё.

## Конвертация

`conv(x, r) = sign(x) · round_policy(|x| · r · 10^(e_base − e_doc))`

- Курс — сколько единиц базовой валюты за 1 единицу валюты документа.
- Дата курса — **местная дата события в часовом поясе компании**
  (`policy.period.timezone`), правило `policy.fx.rate_date`: `same_day_or_previous`
  или `previous_day_or_earlier`, назад не больше `max_lookback_days` (5) дней. На
  выходные курса нет — берётся предыдущий рабочий день.
- Округление `policy.rounding.mode`: `half_even` или `half_up` (ничья — от нуля).
- Время платежей — моменты в UTC из банковской выписки (API банка). Для периода и
  даты курса этот момент переводится во время компании (`policy.period.basis`).

## Правила проводок

| Событие | Проводка |
|---|---|
| Счёт T | Дт 1200 A / Кт 4000 A, A = conv(T) по дате счёта |
| Кредит-нота на полную сумму (аннулирование счёта) | Дт 4100 / Кт 1200 на остаток A счёта; в том же периоде, что и аннулируемый документ |
| Задвоенная и сторнированная проводка | проводка Дт 1200 / Кт 4000, обратная (сторнирующая) Дт 4000 / Кт 1200, затем повторное проведение — все в одном периоде; законный «двойник» ошибки дубля |
| Поступление с разноской сразу | Дт 1010 (conv(P) − conv(fee)), Дт 6100 conv(fee) / Кт 1200 списание задолженности, Кт 2200 conv(переплаты) или Кт 2150 conv(неразнесённой части), ± одна строка 7100 |
| Поступление с разноской в два этапа | 1) Дт 1010, Дт 6100 / Кт 2150 conv(P); 2) через 0–3 дня Дт 2150 X / Кт 1200 ± 7100, где X = conv(P), если разнесён весь платёж, иначе conv(разнесённой части), а остаток остаётся на 2150 |
| Невыясненное поступление | Дт 1010 / Кт 2150, может остаться до конца выгрузки (`invoice_refs = null`) |
| Аванс полученный | Дт 1010 / Кт 2200 (только базовая валюта) |
| Возврат переплаты или аванса покупателю | Дт 2200 / Кт 1010, отрицательная сумма платежа |
| Прочие операции | Дт 62xx / Кт 1010, ссылки null |

`amount_minor` платежа — сумма, которую отправил покупатель (instructed amount,
поле :33B: MT103); `fee_minor` — комиссия, удержанная банком (:71F:). Покупатель
гасит долг на всю `amount_minor`, в банк зачисляется сумма за вычетом комиссии.

## Списание дебиторской задолженности по историческому курсу

- Списание при оплате части `a` счёта T = round(a · A / T), где A — проведённая
  сумма счёта (исторический курс выставления).
- **Закрывающее** списание — событие, после которого разнесённая сумма достигает
  T (`policy.allocation.closing_relief = remainder_on_latest_event`; события
  упорядочены по времени события: платёж, кредит-нота). Оно берёт точный остаток
  A − Σ прежних списаний, поэтому не остаётся «копеек» от округления.
- Строка 7100 — одна на проводку, гасящую 1200; нулевую не создаём.
- Если счёт проведён дважды (ошибка), списание считается от A **одной** проводки.
- Остатки оцениваются на конец выгрузки (`policy.allocation.evaluated_at = export_end`).

## Существенность

Порога существенности нет: любое отклонение от политики — ошибка, если её сумма
не меньше одной основной единицы базовой валюты и не меньше 20 допусков (правило
генератора, см. `policy.findings.materiality`). Небольшие суммы (например,
4,66 EUR по счёту на 1 356 EUR) — это нарушение политики курса, а не суждение о
существенности для отчётности.

## Сумма каждой ошибки

| Тип | Сумма (базовая валюта) |
|---|---|
| `duplicate_invoice` | Дт 1200 любой из двух одинаковых проводок выставления (или проводки одной из копий) |
| `payment_allocation` | завышение дебиторской задолженности по историческому курсу: ожидаемое списание этим платежом − фактическое. Это **не** остаток 2150, который стоит по курсу даты поступления |
| `fx_conversion` | \|Дт 1200 − conv(T, верный курс)\| по счёту или \|Дт 1010 + Дт 6100 − conv(P, верный курс)\| по платежу |
| `period_cutoff` | Дт 1200 сдвинутой проводки счёта или Дт 1010 + Дт 6100 сдвинутой проводки поступления |

Курс начала месяца (`stale_rate`) допустим по IAS 21.22, когда курс меняется
несильно; в VouchAI это ошибка потому, что противоречит объявленной политике
компании (`policy.fx.rate_date`), а не МСФО.

## Инварианты чистых книг

| № | Инвариант |
|---|---|
| I1 | Σ дебет = Σ кредит |
| I2 | каждая проводка (строки одного времени проводки) сбалансирована; у разных проводок разное время |
| I3 | нетто выставления и сторно по счёту: Дт 1200 = conv(T) по дате счёта |
| I4 | по каждому поступлению: Дт 1010 + Дт 6100 = conv(amount) |
| I5 | разница при списании — ровно одна строка 7100 или ноль |
| I6 | остаток 1200 по счёту ≥ 0; у оплаченного или аннулированного = 0 |
| I8 | 2150 по каждому платежу с распределением обнуляется до конца выгрузки |
| I9 | проводка в том же периоде, что и событие (кроме переклассификаций 2150 → 1200) |
| I10 | ID глобально уникальны, все не-null ссылки существуют |
| I12 | ни одной метки ближе 60 с к границам периода |
| I13 | total = Σ amount; amount = quantity × unit_price |
| I14 | в строке ровно одна сторона > 0; валюта = базовая; счёт из плана |
| I15 | каждый документ окна проведён внутри окна |
| I16 | (дата, пара) в fx уникальна; курс > 0 |
| I17 | валюта платежа = валюта счетов в ссылках; Σ распределений ≤ открытой сумме |
| I18 | остаток 2200 по клиенту не уходит в минус во времени |

Номера I7 и I11 зарезервированы (их условия вошли в I6 и I16). Генератор
проверяет инварианты перед внесением ошибок (`books.check_invariants`),
независимый верификатор — по файлам `private/clean/` (отчёт A).

## Упрощения

- Нет переоценки денежных статей в валюте на конец периода (IAS 21.23): ни
  дебиторской задолженности, ни валютных остатков на 1010 и 2150. Поэтому
  списание идёт по историческому курсу.
- Выручка признаётся по дате счёта (`revenue_basis = invoice_date`), а не по IFRS 15.
- Один мультивалютный банковский счёт 1010 (на практике счета ведутся по валютам);
  нет НДС и резервов.
- Кредит-ноты — только на полную сумму, в периоде аннулируемого документа.
- Комиссия банка — процент от суммы (на практике SWIFT-комиссии чаще фиксированные).

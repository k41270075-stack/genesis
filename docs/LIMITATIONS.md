# Честные ограничения

Каждое ограничение — со сценарием, который его воспроизводит, и измеренным
результатом. Команды запускаются из корня репозитория (в контейнере — `/app`).

**Что это не такое.** Программная задача, не профессиональное аудиторское
заключение. Высокая награда агента в VouchAI не доказывает пригодность для
реального аудита. Языковую модель мы не дообучали и не заявляем об улучшении
какой-либо LLM. Обучаемость награды показана на малой политике (REINFORCE,
52 параметра): `reports/LEARNING.md`, строка 13.

| # | Ограничение | Сценарий проверки | Измерено |
|---|---|---|---|
| 1 | **Бухгалтерия упрощена:** нет переоценки валютной дебиторки на конец периода, выручка по дате счёта, один банковский счёт, нет НДС и резервов, кредит-нота аннулирует счёт целиком (`docs/ACCOUNTING.md`) | `python -m vouchai_verify episodes/dev --report` | проверяльщик проходит все эпизоды именно в этой модели учёта; других схем учёта среда не моделирует |
| 2 | **Изоляция в условиях жюри — граница процессов.** Жюри запускает контейнер от USER образа без root (ответ организаторов 21.11), поэтому `make_env()` держит эталон и оценщика в дочернем процессе того же пользователя ОС: процесс политики под тем же пользователем теоретически может прочитать его память средствами ОС. Дополнительный режим (не условия жюри) — запуск от root, где зона оценщика под uid 10001, политика под uid 10002 | `docker run --rm --network none --read-only --tmpfs /tmp --user 0 vouchai eval --isolated --policy simple_reconciler --config jury_like --seeds 0:5 --spy` | шпион под uid 10002 не читает `/proc/<pid>/{environ,maps,mem,fd}` зоны оценщика (CI, шаг docker); на Windows под одним пользователем чтение памяти возможно (проверено через ReadProcessMemory) |
| 3 | **Перебор seed с публичным ключом.** Политика, знающая генератор, может перебрать малые seed и восстановить эпизод. Защита закрытого прогона — секретный ключ `VOUCHAI_KEY`, который видит только зона оценщика, и большие seed | `python -c "import time,vouchai.episode as e; t=time.monotonic(); e.generate_episode(12345,'jury_like'); print(time.monotonic()-t)"` | 0,086 с на seed (`jury_like`, среднее по 20 seed, Intel Core 13-го поколения, один процесс): 10^5 seed — около 2,4 часа на ядро; это и есть причина требовать `VOUCHAI_KEY` в закрытом прогоне |
| 4 | **Свойство общей формулы награды: молчание на чистых книгах.** Пустой ответ на эпизоде без ошибок даёт F1 = 1 (правило кейса) и награду 1,0 при 0 шагов; при многих ошибках экономия шагов может весить больше одного TP. Формулу кейса не меняем (`docs/REWARD.md`) | `python -m vouchai run --policy silence --config clean --seeds 0:10` и `--config jury_like --seeds 0:40` | на `clean` — 1,0; на `jury_like` среднее заметно ниже нуля (см. `reports/FAILURE_ANALYSIS.md`, раздел «Неустранённый предел») |
| 5 | **Нестрогая постановка в пресетах.** В обычных пресетах (`default`, `jury_like`, `L1`–`L5`) ошибка без допустимой цели после половины попыток пропускается и пишется в `provenance.unplaced_errors`, а X1 и X2 подменяют друг друга. Для жюри адаптер и рецепты D01–D20 всегда используют `placement: "strict"`: заказанное ставится ровно так или генерация падает с понятной ошибкой | `python -m vouchai judge-recipes --seeds 0:40` | 800 из 800 эпизодов рецептов: заказанные типы, варианты и сценарии на месте, `unplaced_errors` пуст (`reports/RECIPES.md`); на `jury_like` seed 0–59 без строгого режима — 4 пропуска из 324 заказанных ошибок |
| 6 | **X1 возможен не в каждом мире.** Нужны ненулевое смещение компании, платёж в иностранной валюте у границы периода и разный курс на местную и UTC-дату. Строгий режим перерисовывает события и, если надо, мир (детерминированно от seed), поэтому рецепты D16–D18 закрепляют месяц, начинающийся в будний день | `python -m vouchai judge-recipes --seeds 0:40 --only D16,D17,D18` | сейчас 120 из 120 (seed 0–39); до закрепления месяца было 67 из 75 (seed 0–24), с месяцем, но без перерисовки мира — 119 из 120 |
| 7 | **Время генерации растёт со строгостью.** Рецепт X1 с перерисовками генерируется дольше обычного эпизода. Закрытый эпизод жюри генерирует до `reset`; в режиме train генерация идёт внутри `reset` и входит в 60 секунд | `python -m vouchai judge-recipes --seeds 0:40 --only D18` | только генерация, 10 эпизодов, без параллельной нагрузки: D18 — 0,21 с на эпизод, D06 — 0,19 с; под нагрузкой (несколько прогонов сразу) мы видели до 2,8 с вместе с проверяльщиком — всё равно далеко от 60 с |
| 8 | **Фантомные цели ставятся равномерно, а не под каждый тип отдельно.** Законные «соседи» есть в каждом эпизоде, включая чистые | `python -m vouchai report` → `reports/LEAK_AUDIT.md` | все признаки, включая «число похожих документов рядом», \|AUC − 0,5\| ≤ 0,1 |
| 9 | **Docker у команды не локальный.** Образ собирается и проверяется в CI | CI, задание `docker` | `docker run --network none --read-only --cpus 2 --memory 4g … check` — около 3 минут |
| 10 | **Доказательства — только записи самой компании.** Агент сверяет документы с книгой (vouching / tracing внутри одной компании); внешних подтверждений по ISA 505 (выписка банка, ответ контрагента) в среде нет | `python -m vouchai demo` | скриптовый аудитор находит все ошибки листанием таблиц, без внешних источников |
| 11 | **Скриптовый аудитор и проверяльщик делят детектор.** `vouchai_auditor` использует детектор `vouchai_verify`; независимость проверяльщика — от кода среды, а не от аудитора. Решаемость по открытым данным это показывает, вторую независимую реализацию — нет | `grep -n detect vouchai_verify/auditor.py` | один детектор на оба инструмента |
| 12 | **Пустой ответ лучше случайного.** На общей формуле пустой ответ получает больше, чем случайная политика (−1,0): для RL это риск локального оптимума «молчать»; обучаемый ученик из этого оптимума выходит после 3-го обновления (`reports/LEARNING.md`) | `python -m vouchai run --policy silence --config jury_like --seeds 0:10` | средняя награда молчания печатается в `mean_return` |
| 13 | **Обучена только малая политика.** Ученик — 52 задвижки «советник × тип ошибки», обученные REINFORCE по награде эпизода; он выбирает, кому из советников верить, и не изобретает правила (детектор общий со скриптовым аудитором, строка 11). LLM на этой награде не дообучали | `python -m vouchai_learn` | на 24 отложенных эпизодах −0,426 → +0,968 за 480 обучающих эпизодов (аудитор +0,968); «взломщик» на 11 трюках — не выше молчания (−0,426) за все 30 обновлений |

В закрытом режиме число ошибок агенту не сообщается никак. В режиме train итоговая диагностика (TP/FP/FN) приходит вместе с наградой только после завершения эпизода.
